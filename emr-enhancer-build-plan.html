Since you want the plugin free of that architecture, the plan below does not touch any of it.

Architecture (standalone, zero backend)

  • One file: enhancer.html (HTML + CSS + vanilla JS). No Node, no Postgres, no build step.
  • BYOK: user pastes an OpenRouter or Anthropic key; stored in localStorage, sent only to the LLM provider. Demo mode with canned snake-bite schema works with no key.
  • Storage: schemas and cases in localStorage/IndexedDB; JSON export/import.
  • Validation layer (JS): a small bundled table of verified SNOMED/LOINC codes + schema checks. Anything the LLM returns that is not in the table is flagged "unverified", never silently trusted.
  • Later, optional: embed in VibeRounds via <iframe src="enhancer.html"> as a new tab, with zero coupling.
Check before publishing. The Gemini draft's example codes (e.g. SNOMED 20246006, LOINC 89257-3, 32434-6) are not verified, and LLMs commonly invent plausible-looking codes. Look up every code you show in a demo or article in a SNOMED browser (e.g. browser.ihtsdotools.org) and LOINC search (loinc.org) and put only verified ones in the seed table (Chunk 4). Also label the demo "not for clinical use" and use synthetic cases only.

SMART on FHIR version (built). Files: smart-launch.html, enhancer-smart.html, proxy.js.
  1. Put the two HTML files in one folder served over https (GitHub Pages works) or http://localhost: npx http-server -p 8080.
  2. Start the proxy: OPENROUTER_API_KEY=… MODEL=… ALLOW_ORIGIN=http://localhost:8080 node proxy.js.
  3. Open launch.smarthealthit.org, choose Provider Launch, pick a synthetic patient, set App Launch URL to your smart-launch.html URL, launch.
  4. In the app Settings paste the proxy URL (http://localhost:3100). Pick an active condition, generate, fill, Build bundle, Send to EMR.
Verify the fhirclient version pin (2.5.2) exists on jsdelivr before relying on it.
